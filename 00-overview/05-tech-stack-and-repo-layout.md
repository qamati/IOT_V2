# 05 — Tech Stack, Decisions & Repository Layout

## 1. Architecture decision records (summary)

| ADR | Decision | Why | Revisit when |
|---|---|---|---|
| D1 | **Modular monolith first**, services split by build target (`cmd/*`), not by repo | Fast iteration; one `iotp-lite` binary; split only where scaling/isolation demands | A module needs independent scaling/SLA |
| D2 | **Go ≥ 1.24** (use latest stable) | Goroutines suit connection/stream workloads; static binaries for edge | — |
| D3 | **PostgreSQL 16** system of record | Mature, RLS, JSONB, partitioning | Multi-region writes needed |
| D4 | **TimescaleDB default, ClickHouse optional, SQLite at edge/lite** behind `tsstore.Store` | Operational familiarity first; scale path later | > 100 k rows/s sustained |
| D5 | **Kafka** (cluster) / **NATS JetStream** (lite, edge) / in-memory (tests) behind `bus` | Same semantics, different ops cost | — |
| D6 | **Protobuf + buf** for internal gRPC and bus; **OpenAPI-first** for public REST | Contract safety, codegen both ends | — |
| D7 | **Device API v1 = ThingsBoard wire-compatible** | Instant ecosystem (SDKs, gateways, devices) | Legal review says otherwise |
| D8 | **Scripts:** `expr` (default), `goja` (JS compat), **WASM via wazero** (third-party plugins) | Safe sandboxing, no cgo | — |
| D9 | **UUIDv7** IDs | Index locality | — |
| D10 | **Tenancy:** shared schema + `tenant_id` + RLS; L2–L4 isolation levels per profile | Cost-efficient default, upgrade path | — |
| D11 | **React + TypeScript + Vite**, pnpm workspace | Ecosystem, hiring | — |
| D12 | **Widgets as ESM modules** with manifest; untrusted ones in sandboxed iframes | Security + dev experience | — |
| D13 | **OpenTelemetry** for traces/metrics/logs; trace context inside bus envelopes | End-to-end debugging | — |
| D14 | **Expand/contract DB migrations**, rolling upgrades | Zero-downtime | — |

ADR template (`docs/adr/NNNN-title.md`): *Context · Decision · Alternatives · Consequences · Status (proposed/accepted/superseded)*.

## 4. Repository layout (single Go module + pnpm workspace)

```
iotp/
├── api/
│   ├── proto/iotp/{core,devreg,telemetry,bus,edge,scada}/v1/*.proto
│   ├── openapi/openapi.yaml
│   └── asyncapi/asyncapi.yaml
├── cmd/
│   ├── apigw/ identity/ core/ devreg/ devstate/ ruleengine/ telemetry/ alarm/ notify/
│   ├── rpc/ ota/ realtime/ dashboard/ integration/ scheduler/ reporter/ audit/
│   ├── tr-mqtt/ tr-http/ tr-coap/ tr-lwm2m/ tr-snmp/
│   ├── edge-hub/ edge/ field-gateway/ scada/ analytics/
│   ├── iotp-lite/            # everything in one process
│   └── iotpctl/              # migrations, DLQ replay, import/export, load-gen
├── internal/                 # service-private (hexagonal)
│   └── <service>/{domain,app,infra,api}
├── pkg/                      # shared, edge-safe libraries
│   ├── bus/{mem,nats,kafka}  ├── tsstore/{timescale,clickhouse,sqlite}
│   ├── blobstore/            ├── cache/
│   ├── shard/                # sharded executor (actor-lite)
│   ├── rules/                # rule engine core lib (cloud + edge)
│   ├── script/{expr,goja,wasm}
│   ├── connectors/           # shared by field-gateway + edge
│   ├── auth/ ids/ errs/ obs/ config/ ratelimit/ tenancy/ testkit/
│   └── sdk/                  # public plugin SDK (separate module later)
├── db/{migrations,queries}   # goose + sqlc
├── deploy/{compose,helm,terraform,k6}
├── tools/{loadgen,device-sim,codegen}
├── web/                      # pnpm workspace
│   ├── apps/{console,edge-ui,docs}
│   └── packages/{ui,sdk,widgets,charts,rule-editor,scada,api-client}
├── docs/{adr,specs,runbooks}   # specs = this pack
├── Taskfile.yml  go.mod  buf.yaml  sqlc.yaml  .golangci.yml  .github/workflows/
```

**Rules**
- `internal/*` may not import other services' `internal`; cross-service use gRPC/bus contracts only.
- `pkg/*` must compile for `linux/{amd64,arm64,armv7}` and avoid cgo (edge portability).
- Composition roots live only in `cmd/*/main.go`.
- Domain packages have no dependency on transport/DB packages (ports & adapters).

## 5. Coding conventions

- `context.Context` first parameter; propagate deadlines; never store contexts in structs.
- Errors: wrap with `%w`; map to API errors in one place (`pkg/errs`); no panics across package boundaries.
- Logging: structured, one line per event; never log secrets/tokens/payload bodies by default.
- Concurrency: every goroutine has an owner and a stop signal (`errgroup`); bounded channels; no unbounded fan-out.
- Interfaces are defined by the **consumer**; keep them tiny.
- Tests: table-driven; fakes over mocks; integration tests via testcontainers; golden files for API/ proto.
- Metrics naming: `iotp_<service>_<noun>_<unit>`; labels never include unbounded values (device IDs).
- Config: no defaults hidden in code; every option documented in `docs/config.md` (generated).

## 6. CI/CD pipeline

| Stage | Tools |
|---|---|
| Lint & static | golangci-lint, `buf lint`, `buf breaking`, eslint, tsc, `sqlc vet` |
| Unit | `go test -race -shuffle=on`, vitest |
| Integration | testcontainers (Postgres, Timescale, Kafka/NATS, Redis, MinIO) |
| Contract | MQTT/HTTP device transcripts, OpenAPI diff, proto breaking checks |
| Security | govulncheck, gosec, trivy (images), gitleaks, license scan |
| Build | `ko`/Docker multi-arch; goreleaser for `edge`, `field-gateway`, `iotpctl` |
| E2E | docker-compose stack + Playwright flows |
| Perf (nightly) | k6/loadgen scenarios with regression gates (stage 15) |
| Release | SBOM (syft), signing (cosign), Helm chart publish, changelog |

**Branching:** trunk-based, short-lived branches; `release/x.y` for LTS lines; semantic versioning; DB changes follow **expand → migrate → contract** across two releases; edge/cloud protocol compatibility window N-2 (see `services/22`).

## 7. Local developer environment

`task dev` brings up: Postgres+Timescale, Redis, NATS (or Kafka via Redpanda), MinIO, Mailpit (SMTP), Grafana/Prometheus/Tempo/Loki, and `iotp-lite` with hot-reload (`air`/`watchexec`); `task seed` creates a demo tenant, 100 simulated devices and sample dashboards; `task test:e2e` runs Playwright against it.
